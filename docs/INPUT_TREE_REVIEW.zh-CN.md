## 差距与最小设计

初审指出仅有文法校验，建议输入树和真实协议验证。旧 `parse(Bytes)` 返回文法
`Grammar/Expr` AST，旧 `recognize` 仅传播端点；旧自造Trace字段不是标准协议实证。
本轮保留旧编译/识别接口，增加 `Program::parse_input` 和独立的 `InputTreeReport`。

| 决策 | 实现契约 |
|---|---|
| 输出结构 | 一棵完整输入派生，平坦nodes数组、root=0、规则/终端/序列/分支索引/实际重复次数与孩子ID；最终只保留可达节点 |
| 字节位置 | start/end为零起始半开输入字节跨度，原input切片直接提取；source_offset另指文法表达式，隐式core为合成位置0 |
| 无序替代 | 各替代均探索，所有不同结束偏移都传播；首分支只决定同端点见证，不影响后续序列的可匹配语言 |
| 歧义 | 每端点一棵首次遇到的见证，重复次数按升序、精确次数内保留首路径；不枚举所有树，不检测唯一性，改写等价文法可改变选树 |
| 递归 | 延续编译期拒绝左递归/可空前缀循环；允许消耗字节递归，运行受最大128调用深度约束 |
| 可空重复 | 在树里真实生成最小次数的子节点；端点稳定且已经满足最小次数后才停止；百万空重复可能recognize成功而树预算耗尽 |
| 预算 | matching沿用MatchLimits合法范围；树默认节点20,000/子边与路径40,000，硬上限100,000/200,000；探索、丢弃分支、路径列表、孩子数组、最终压缩累计计费 |
| 工作与错误 | 额外计树分配、路径复制/反转；与recognize计数不同。先非法预算、再输入长度、再入口；后续分支或压缩失败也不能返回此前发现的部分树 |

同端点去重足以供上下文无关延续使用，后续只依赖结束位置而不依赖见证内容。
内部追加路径为平坦索引链，避免反复复制前缀和深链析构；最终树亦用迭代压缩。
分配数不是峰值内存字节；SDK开销、入口名归一化不纳入操作计数，无墙钟或进程内存保证。
大量歧义/宽重复仍可能耗尽默认预算，不承诺所有合法文法和输入都能输出树。

## 真实规范场景

`examples/http_etag/main.mbt` 文法来自 [RFC9110 §8.8.3](https://www.rfc-editor.org/rfc/rfc9110.html#section-8.8.3)
和 [§5.5](https://www.rfc-editor.org/rfc/rfc9110.html#section-5.5)，单独保留IETF BSD归属。
`cmd`示例编译一次，解析字段值 `W/"revision-7"`，从规则树提取weak=true、内容字节跨度[3,13)。
测试包含空标签、反斜杠原样保留、高位字节、非法前缀/字符/后缀及全部256内部字节。
覆盖仅为ETag字段值语法与提取；不含外部空白/字段行包装、HTTP完整消息、
验证器生成、标签比较或条件请求语义。它是规范驱动的集成例子，并非线上真实流量或第三方采用证明。

## 用户后续复验与申报修改要点

Mac恢复或可用可信完整SDK后，设置MOONABNF_SDK并运行 `scripts/moon-local.sh info`、
`scripts/moon-local.sh fmt --check`、`python3 scripts/acceptance.py --output <新目录>`，
再用四后端运行 `examples/http_etag/cmd`。新证据必须对应本补丁，不沿用历史323a3728结果。
尚未验证：完整SDK四后端执行、Windows、LLVM、浏览器、多线程、第三方完整ABNF差分、
全协议/业务语义、真实第三方采用、注册表新版本消费和远端CI。

给人工修改申报书的事实要点：

1. 区分文法AST、编译校验、识别与输入派生树，指出新API和可检查的规则/字节结果。
2. 描述无序替代及一棵歧义见证策略，公开左递归、预算与百万可空重复限制。
3. 将原自造协议字段与RFC9110规范场景分开，列提取结果、拒绝测试、来源和覆盖边界。
4. 如实写JS通过与其余后端阻塞；不能使用“全部四后端通过”或“完整HTTP解析器”。
5. 先理解和复验，再由用户本人写最终申报，本人处理身份材料与诚信声明。
